Ultimate MiniLED Dimming（无分区 Mini LED 控光）技术拆解

面向无物理分区边界（Zone-free）的 Mini LED 背光控光方案，从技术背景、硬件设计、软件（算法）设计三个维度， 拆解其如何在提升对比度、压低黑场、抑制光晕（Halo）之间取得平衡的基本做法。

01

技术背景

1.1 背光控光技术的演进

LCD 面板本身不发光，画面明暗完全依赖背光模组配合液晶偏转来"遮光"实现。这决定了 LCD 的对比度上限、黑场表现始终受限于背光系统的精细度：

阶段技术方案控光粒度典型问题
1侧入式背光 / 直下式全局调光整屏一档亮度无法局部压暗，黑场发灰
2FALD（全阵列直下式局部调光）传统 LED数十～数百分区分区大，光晕明显，块状伪影
3Mini LED 分区背光（Zone-based Local Dimming）数百～数千分区分区仍有物理边界，高光小面积仍会晕开
4无分区 / Zone-free 控光（Ultimate MiniLED Dimming 所属类别）逐灯珠 / 亚分区级、算法拟合到近似像素级需要极高算力与驱动带宽

1.2 传统"分区背光"的物理局限

即便 Mini LED 把物理分区数从几百堆到几千甚至上万，只要控光逻辑仍以"矩形分区（Zone）"为最小控制单元，就会存在两个绕不开的问题：

  • 分区边界效应：同一分区内亮暗内容混合时，只能取一个折中亮度，导致小面积高光（如星空、字幕）四周产生光晕（Halo）／泛光（Blooming）。
  • 光学串扰（Light Crosstalk）：相邻分区的光通过扩散层互相渗透，分区数越多，理论精细度越高，但边界渗透带来的"伪影"反而可能更容易被肉眼察觉。

1.3 "无分区"（Zoneless / Zone-free）思路的提出

无分区控光的核心思想是：不再把背光简单划成固定矩形网格，而是把每颗（或每一小簇）Mini LED 都当作一个近似独立可控的"虚拟像素"， 通过算法建模每颗 LED 的光学扩散特性（点扩散函数，PSF），结合目标画面的亮度分布做反向解算（Deconvolution）， 计算出一套"驱动矩阵"，使合成后的光斑叠加结果尽可能逼近画面本身的亮暗轮廓，而不是停留在"整块区域一个亮度值"的粗粒度。

可以理解为：传统分区背光是"打格子填色"，无分区控光更接近"用成百上千个可调光斑做卷积拟合"， 目标是让背光的空间分辨率尽量逼近画面内容的空间分辨率，从而同时压低黑场、抬高对比度、收窄光晕范围。

1.4 Ultimate MiniLED Dimming 的功能定位

作为一项 PQ（Picture Quality）功能，其目标可以归纳为三个核心画质指标的联合优化：

对比度（Contrast）
提升同一帧内最亮与最暗区域的动态范围表现，让 HDR 内容的层次感更真实。
黑场（Black Level）
在暗场/纯黑内容中尽可能逼近"关灯"状态，减少灰雾感（Grey Mist）。
光晕控制（Halo Control）
抑制高亮小物体（字幕、高光点）周围因背光扩散造成的可见光斑外溢。
三者的张力
三个目标天然存在博弈：压暗越狠越容易黑场好但可能误伤暗部细节；光晕抑制越强，高光亮度可能被牺牲——无分区算法本质上是在做多目标的实时联合优化。
02

硬件设计

无分区控光能否成立，首先取决于硬件层面是否具备"高密度、高速、高灰阶、可精细寻址"的物理基础，这是软件算法能够生效的前提。

2.1 Mini LED 芯片与封装

  • 倒装芯片（Flip-Chip）封装：省去打线工艺，芯片尺寸可做到 100~200μm 级别，便于在同等面积内堆叠更高密度的灯珠，为"逐灯珠寻址"提供物理密度基础。
  • 芯片间距（Pitch）压缩：灯珠间距越小，单位面积内可独立控制的光源数量越多，光学混合后的等效控光粒度越接近像素级。
  • 光学微透镜 / 二次光学设计：控制单颗 LED 的发光角度与光斑扩散半径，直接决定后续算法建模 PSF（点扩散函数）时的基础参数。

2.2 阵列驱动架构：AM vs PM

驱动方式特点与无分区控光的关系
PM（被动矩阵）每个分区独立走线，分区数受布线与驱动通道数限制分区数越多布线越复杂，难以支撑"近像素级"密度
AM（主动矩阵，TFT 背板驱动）类似面板驱动方式，用薄膜晶体管背板做寻址，可大幅提升可控光源数量而不显著增加走线复杂度是实现无分区、超高密度控光的关键使能技术之一

2.3 驱动 IC 与灰阶精度

  • 多通道驱动芯片：单颗驱动 IC 需要支持大量输出通道，并通过菊花链（Daisy Chain）/ SPI 高速总线级联，保证成千上万颗 LED 能在一帧时间内完成刷新。
  • 高比特灰阶控制（如 12bit / 14bit）：分区越"无形化"，越依赖每颗 LED 自身的亮度级数足够细腻，否则算法解算出的连续亮度值会因量化误差重新出现台阶感。
  • PWM 与电流双重调光：PWM 频率需远高于人眼闪烁感知阈值（通常数千 Hz 级），并结合恒流驱动，避免不同亮度下的色温漂移。

2.4 光学结构：从"扩散"到"可预测的扩散"

无分区算法要做反向解算，前提是每颗 LED 的光斑扩散规律是可测量、可建模、且相对稳定的。因此硬件光学堆叠（扩散板厚度、雾度、量子点膜层、微透镜阵列） 需要在"均匀性"和"局部对比可控性"之间做工程取舍：扩散越强，画面越均匀但局部对比与响应速度下降；扩散越弱，局部对比更强但更依赖驱动精度，否则容易露出灯珠颗粒感（Lamp Mura）。

2.5 热管理与灰阶一致性

  • 高密度 Mini LED 阵列在高负载画面（大面积高亮）下功耗与热量集中，需要金属基板 / 导热界面材料（TIM）优化散热路径。
  • 温度漂移会影响 LED 的光效与色坐标，因此通常会配合温度传感反馈，动态修正驱动电流，保证无分区算法输出的"目标亮度矩阵"在实际发光端不失真。

2.6 传感与反馈闭环

  • 环境光传感器：为整体亮度基线与 ABL（自动亮度限制）策略提供输入。
  • 电流 / 温度反馈：驱动 IC 层面的闭环校正，确保"软件算出的目标值"与"硬件实际发出的光"尽量一致，这是无分区算法精度的下限保证。
03

软件（算法）设计

如果说硬件解决的是"能不能精细发光"，软件算法解决的是"该怎么发光"。无分区控光的算法核心，是把传统"按分区取均值"的简单逻辑， 升级为一套图像分析 → 光学建模 → 反向解算 → 时域/空域平滑 → 光晕抑制的完整实时流水线。

3.1 逐帧图像分析引擎

  • 对输入帧做多尺度亮度直方图分析，提取全局最大/最小亮度、局部亮度梯度、高光面积占比等特征。
  • 识别"关键结构"：小面积高亮点（如星空、灯光）、大面积暗场、字幕/UI 叠加层等，这些区域往往是光晕与黑场问题最敏感的地方，需要单独打标签供后续算法加权处理。

3.2 点扩散函数（PSF）建模

每颗 Mini LED 经过硬件光学堆叠后，在屏幕表面会形成一个近似高斯分布的光斑。算法预先（出厂标定阶段）对每颗灯珠或每个子区域的 PSF 参数进行测量与建模， 得到一个"灯珠位置 → 屏幕亮度贡献"的响应矩阵，这是后续反向解算的数学基础。

3.3 反向解算 / 光场逆卷积（Deconvolution）

目标：给定画面希望呈现的理想亮度分布 I(x, y)，求解一组灯珠驱动值 D，使得 D 经过 PSF 卷积后的合成光场尽量逼近 I(x, y)， 同时满足约束条件（不能为负、不能超过灯珠最大电流、总功耗不能超限）。这本质上是一个带约束的最优化问题，常见做法包括：

  • 迭代逼近法：类似图像复原领域的 Richardson–Lucy 反卷积思路，多轮迭代逐步收敛到最优驱动矩阵。
  • 查找表 + 局部修正：出厂预置典型场景的驱动模式库，运行时先查表取近似解，再用轻量算法做局部微调，兼顾实时性与效果。
  • 神经网络推理：部分新一代方案会用轻量卷积网络直接从画面预测驱动矩阵，替代显式的光学逆卷积计算，以降低实时算力开销。

3.4 光晕抑制（Halo Suppression）联动

单纯的逆卷积解算容易在高光边缘"过冲"（Overshoot），造成新的光晕；因此通常会引入：

  • 亮度提升与压制的双向限幅（Boost/Clip Limiter）：对高光周边灯珠的提亮幅度设置软限制，防止边界过亮。
  • 与 Tone Mapping 联动：背光解算结果会反馈给液晶端的灰阶映射曲线（Pixel Compensation），由背光负责"大轮廓"压暗/提亮，液晶负责"精细补偿"，两者协同减少视觉可察觉的光晕残留。

3.5 时域平滑与防闪烁

  • 逐帧独立解算容易在运动画面中出现背光"呼吸感"或闪烁；因此会引入帧间低通滤波 / 运动矢量估计，让背光亮度变化在时间轴上保持平滑过渡。
  • 对纯静态暗场（如黑屏字幕）则反向操作：快速收敛到极低亮度，避免长时间"黑不下去"的灰雾感。

3.6 动态范围映射与 ABL 联动

  • 结合 HDR 内容的 EOTF（如 PQ/HLG）曲线，将解算出的背光目标值与整机的自动亮度限制（ABL）、功耗预算做联合调度，避免大面积高亮画面因功耗墙触发整体降亮，抵消无分区算法带来的局部对比收益。
  • 场景识别模块（电影/游戏/体育等模式）会调整算法的"激进程度"参数，例如游戏模式优先响应速度、电影模式优先对比与黑场精度。

3.7 算法与驱动 IC 的实时协同

解算出的驱动矩阵最终需要在极短时间内（通常与面板刷新率同步，如 1/120s 级别）下发给数千通道的驱动 IC， 这要求 PQ 处理芯片（ASIC/FPGA）具备足够的并行计算能力与高速总线带宽，是软件算法能否"跑起来"而不掉帧的硬件保障。

端到端工作流程

综合硬件与软件两侧，一个典型的无分区 Mini LED 控光处理链路可以概括为：

输入帧解码 / HDR元数据解析
→
图像特征分析
（亮度直方图/关键结构识别）
→
目标光场建模
（结合PSF响应矩阵）
→
反向解算
求解驱动矩阵
→
光晕限幅 +
时域平滑
→
与液晶Tone Mapping
协同补偿
→
驱动IC高速下发
（AM背板寻址）
→

整条链路需要在一帧的时间预算内闭环完成，任一环节的延迟都会直接反映为响应拖影或背光跟不上画面变化。

05

优势与挑战

相对传统分区背光的收益

  • 光晕范围显著收窄，小面积高光更"干净"
  • 暗场黑位更接近纯黑，对比度提升明显
  • 细节层次感更接近自发光显示的观感

随之而来的工程挑战

  • 算力与带宽需求大幅上升（实时反卷积/AI推理）
  • 需要极高精度的出厂光学标定（PSF建模）
  • 高密度AM驱动背板与多通道IC带来成本压力
  • 算法激进程度需在效果与功耗/温漂稳定性间反复调校
06

小结

"无分区 Mini LED 控光"类 PQ 功能（如 Ultimate MiniLED Dimming 所代表的这一类技术），本质上是把 LCD 背光控制从 "按矩形分区取均值"的粗粒度逻辑，升级为"以每颗灯珠光学响应为基础的连续光场反向解算"的精细化逻辑。 它的成立依赖硬件（高密度Flip-Chip灯珠、AM主动矩阵驱动、可预测的光学扩散、高比特灰阶驱动IC）与软件（PSF建模、反向解算、光晕限幅、时域平滑、与液晶补偿协同） 两侧同时到位，二者缺一不可：硬件决定了"控光的物理上限"，软件决定了"这个上限能被多大程度地兑现为肉眼可感知的对比度、黑场与光晕改善"。
